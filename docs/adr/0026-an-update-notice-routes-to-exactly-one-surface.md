# An Update Notice routes to exactly one surface

TokenLedger is tray-resident, so an update can need announcing when no webview exists — a hidden at-login start creates none, and closing the window destroys it while the app stays recording. An Update Notice (a release is available, or a relaunch applied one) is therefore announced on exactly one surface. When a main window is visible, that surface is the window's own: the update card, Settings dot, and Settings banner of TOKL-21, driven by the frontend's mount- and focus-time checks. When none is, the surface is an OS notification posted from Rust: the relaunch notice at setup on a hidden start, and a daily resident update check carried as its own deadline on the capture loop, which reads the auto-check setting on every tick, skips whenever the main window is visible, and notifies at most once per version per run. Rust owns the only memory of the last-run version (`last-version` in the app data dir); the window's "Updated" card collects the climb through the take-once `applied_update` command rather than keeping a second record, so one applied update is announced exactly once and never with a stale "from", and the version comparator exists once, in `updater.rs`. Deliberately uncovered: a visible-but-backgrounded window belongs to the card, not to a duplicate notification; and desktop notifications carry no click action, so the body says where to act instead. Notification copy follows the two app languages, like the Menu Bar Extra's readout.
