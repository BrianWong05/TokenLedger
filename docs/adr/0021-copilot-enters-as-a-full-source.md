# Copilot enters as a full Source, not a Limits-only card

GitHub Copilot will not enter the Source Catalog solely because its vendor can report subscription Limits. Its production entry must also pass the existing evidence gate with a genuine native local Source Artifact that yields trustworthy non-zero token Usage Records; once admitted, the same Source may expose Limits through a Companion. Private metadata-only validation of standalone Copilot CLI 1.0.79 confirmed schema version 6 of `~/.copilot/session-store.db`: its native `assistant_usage_events` table produced a per-request record with stable identity, Session, Model, timestamp, and non-zero input, output, and reasoning tokens. That database is therefore Copilot's first supported Artifact; TokenLedger will not install a hook, collector, or telemetry export to manufacture another. Those records participate in TokenLedger's normal Est. cost calculation at publisher API List Prices; as Cost already defines, this is a hypothetical API-price equivalent rather than Copilot spend or Premium Request consumption. Other Copilot surfaces remain part of the same Source but require independent Artifact validation before their records are ingested. Locally observed Usage Records may cover fewer Copilot surfaces than its account-wide Limits; the gap is disclosed and never estimated from credit consumption.
